## Physical-device execution sheet

Use only the debug APK generated by the Android workflow for the exact accepted PR HEAD. Record the artifact's commit SHA and APK SHA-256 before installation.

1. Install on the Samsung Galaxy A16 / Android 16. Record install result and package version.
2. Launch from a cold start. Record time to interactive content, splash branding and any blank/error screen.
3. Verify Amharic-first welcome, Ethiopic glyph shaping, English switching and text clipping at system font scaling.
4. Verify header/navigation, dashboard cards, wallet/map/profile/help/report screens and back navigation. Record any screen that is presentation-only or disconnected from an API.
5. Exercise keyboard appearance, form validation, password visibility, date/file inputs where available, scrolling, rotation and resume after backgrounding.
6. Test Wi-Fi to mobile-data transition, offline launch, loss/recovery feedback and retry behavior. Do not assume unsent changes are synchronized.
7. Review crash behavior and Android logs for fatal exceptions, WebView renderer loss, CSP errors and repeated network failures.
8. Record screenshots or short recordings for each failure and mark each row PASS / FAIL / BLOCKED. Do not upload personal or real compliance documents.

### Physical-device release blockers already known

Passenger self-registration/session API, persisted passenger profile edits, connected password recovery, live map/geolocation/routes, end-to-end passenger journey search/booking, customer wallet integration, payment adapters, support ticket persistence, report persistence/attachments and durable offline queue/synchronization are not established by the current baseline. Their UI presence must not be mistaken for operational functionality. Real-money movement remains disabled.
